# AIInterviewer — 技术架构说明书

> 鸿蒙高校创新赛 · 应用创新赛道 · AI 模拟面试官

## 一、项目概述

**AIInterviewer** 是一款基于大语言模型（LLM）的智能面试陪练应用，运行于 HarmonyOS 平台。用户输入任意岗位的 JD（职位描述），应用自动解析关键要求、生成针对性面试题、进行多轮追问并输出三维度评估报告。目标用户为求职者、应届生和转行者，帮助其在真实面试前进行无压力的模拟练习。

---

## 二、技术选型

| 维度 | 选用技术 | 选型理由 |
|---|---|---|
| 开发框架 | ArkUI 声明式 + Stage 模型 | HarmonyOS 原生推荐，声明式 UI 开发效率高 |
| 编程语言 | ArkTS | 类型安全，面向对象的 TS 超集，适合大型应用 |
| 构建工具 | Hvigor | HarmonyOS 官方构建系统，集成 DevEco Studio |
| 网络请求 | `@ohos.net.http` | 零外部依赖，原生支持 HTTPS 和流式响应 |
| 数据持久化 | `@ohos.data.preferences` | KV 存储，适合配置类数据，无需额外依赖 |
| AI 能力 | LLM API（兼容 OpenAI 格式） | 灵活接入多种模型，prompt 可控性高 |
| 日志 | `@kit.PerformanceAnalysisKit` / `hilog` | 原生性能分析套件，支持分级日志 |

**零第三方依赖**。网络、存储、日志全部走 HarmonyOS 原生 Kit，不引入额外运行时。

## 三、系统架构

### 3.1 整体架构

```
┌──────────────────────────────────────────────────────────┐
│                     UI 表现层 (ArkUI)                     │
│  ┌──────────┐  ┌──────────────┐  ┌──────────────────┐   │
│  │ Index    │  │ Interview    │  │ Report           │   │
│  │ 首页/JD  │→ │ 面试答题+追问 │→ │ 三维度评分报告    │   │
│  │ 输入     │  │              │  │                  │   │
│  └──────────┘  └──────────────┘  └──────────────────┘   │
├──────────────────────────────────────────────────────────┤
│                    业务逻辑层 (utils)                     │
│  ┌────────────────┐  ┌──────────┐  ┌──────────────┐    │
│  │ PreferencesMgr │  │ http.ts  │  │ prompt.ts    │    │
│  │ API Key 管理   │  │ 网络请求  │  │ 提示词工程    │    │
│  └────────────────┘  └──────────┘  └──────────────┘    │
├──────────────────────────────────────────────────────────┤
│                    系统能力层 (Kit)                       │
│  ┌──────────────┐  ┌────────────┐  ┌───────────────┐   │
│  │ ArkData      │  │ NetworkKit │  │ Performance   │   │
│  │ (Preferences)│  │ (http)     │  │ AnalysisKit   │   │
│  └──────────────┘  └────────────┘  └───────────────┘   │
├──────────────────────────────────────────────────────────┤
│                     AI 能力层 (外部)                      │
│              ┌──────────────────────────┐               │
│              │   LLM 大语言模型 API     │               │
│              │  GPT-4 / 文心 / 通义等   │               │
│              └──────────────────────────┘               │
└──────────────────────────────────────────────────────────┘
```

### 3.2 架构设计原则

1. **单向依赖**：UI 层 → 业务逻辑层 → 系统能力层，禁止反向调用
2. **接口隔离**：每层通过明确接口暴露能力，内部实现可独立替换
3. **可替换 AI 后端**：LLM API 层基于 HTTP 协议，兼容任何 OpenAI 格式接口
4. **无外部 SDK**：全部使用 HarmonyOS 原生 Kit，避免兼容性风险

## 四、核心业务流程

```
┌──────────┐    ┌───────────┐    ┌──────────┐    ┌─────────┐
│ JD 输入   │───→│ LLM 解析  │───→│ 生成面试题│───→│ 用户回答 │
│ (用户粘贴) │    │ (prompt)  │    │ (prompt)  │    │ (输入)   │
└──────────┘    └───────────┘    └──────────┘    └─────────┘
                                                      │
                                                    第一轮
                                                      │
                                                      ▼
┌──────────┐    ┌───────────┐    ┌──────────┐         │
│ 评分报告  │←───│ LLM 分析  │←───│ 智能追问 │←────────┘
│ 三维度    │    │ (prompt)  │    │ (最多3轮) │  循环追问
└──────────┘    └───────────┘    └──────────┘
```

### 流程详解

1. **JD 输入与配置**：用户粘贴岗位 JD 文本，首次使用需配置 LLM API Key（Preferences 持久化）
2. **JD 智能解析**：发送 JD 文本至 LLM，提取职位名称、关键要求、职责描述、技能关键词
3. **面试题生成**：基于解析结果生成针对性面试题（技术/行为/项目经验三类型混合）
4. **多轮追问（核心创新）**：用户回答后，LLM 根据回答内容生成追问，深入考察（最多三轮）
5. **三维度评分**：所有问答结束后，LLM 从技术深度、表达沟通、逻辑思维三个维度评分并给出改进建议

## 六、数据安全与隐私

### 6.1 API Key 保护

- API Key 通过 `@ohos.data.preferences` 存储在应用私有目录
- 代码中不包含任何硬编码 Key
- 日志输出过滤敏感信息（`%{private}s`）

### 6.2 用户数据保护

- 面试问答数据仅在内存和 router params 中流转，不落盘
- 除 LLM API 调用外，不向任何第三方传输用户数据
- 数据在页面退出时自动释放

### 6.3 网络安全

- 所有 API 请求使用 HTTPS 传输
- 无明文存储用户面试内容到外部存储

## 八、可扩展性

- **可替换 AI 模型**：通过 `prompt.ts` 统一管理提示词，更换后端只需修改请求端点
- **可增加面试类型**：新增 `QuestionType` 枚举值和对应 prompt 模板即可
- **可扩展到更多题型**：支持编程题、场景模拟题等扩展
- **可接入语音输入**：在 Interview 页面接入 `@ohos.multimedia.audio` 实现语音作答
